# 読者の環境から手順をたどる

まず記事の到達点を、読者が観測できる動作に置き換える。開始時に必要なバージョン、権限、既存設定のうち、手順の成否を左右するものを拾う。

- コマンドを掲載順に読み、どの端末・ユーザー・ディレクトリで実行するかを追う。ホストからゲストへ移る箇所や、別のシェルを開く箇所では、ファイルや変数を次の手順でも参照できるか確かめる。
- プレースホルダーは値の取得元まで示す。前の手順で作成した名前やパスは、後のコマンドが実際に参照するものと照合する。
- 読者が次へ進んでよいか迷う箇所には、成功を見分ける出力や状態を添える。最後は記事の目的に対応する操作で確かめる。たとえばサービスへの接続が目的なら、プロセスの起動確認に続けて接続結果を示す。
- 初期化や上書きなど、読者の既存データに影響する手順は、対象の識別方法と実行後に変わるものを直前に示す。

レビュー結果は「読者が止まる手順」「足りない前提や確認」「その場に追加する文またはコマンド」で返す。実行して確認した範囲と、原稿や設定を照合して確認した範囲を区別する。
