# 障害調査の判断をたどれる記事を書く

冒頭で、どんな環境で誰にどんな症状が出たかを示す。原因が分かっている場合は短く先に伝え、本文では当時の観測からその判断に至った道筋を再現する。

1. ログ、監視値、作業メモを照合し、発生前の正常状態、最初の異常、切り分けに効いた観測、復旧確認を拾う。時刻を突き合わせるときはタイムゾーンと観測元をそろえる。
2. 調査の分岐ごとに「何を疑ったか」「何を確かめたか」「その結果で候補がどう絞れたか」をつなぐ。あとから判明した事情は、それが分かった場面で説明する。記録にない仮説や試行は補わない。
3. 復旧操作と復旧確認を対で書く。たとえば再起動の後、利用者が失敗していた操作を再試行して成功したなら、その結果まで示す。原因や恒久対策の効果は、確認できた範囲を明記する。

複数の機器やサービスの出来事が重なる場合は、時刻・観測元・出来事を短い表にする。最後に、同じ症状を見た読者が最初に確認できるログや指標と、その結果によって次に見る場所を示す。
