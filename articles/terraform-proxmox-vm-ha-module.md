## はじめに

本記事は、Proxmox VE 上の仮想マシン（VM）の定義を 1 つの Terraform モジュールにまとめた設計を説明します。

VM を 1 台作る作業には、IP アドレスの払い出し、cloud-init の設定、Proxmox VE の高可用性（HA）への登録、ファイアウォールの設定が含まれます。

これらを VM ごとに個別に書くと、定義の書き方が VM ごとに分かれます。

モジュールにまとめることで、呼び出し側は名前と配置先ネットワークとリソース量を指定するだけで済みます。

対象のモジュールは `vm_ha_node` という名前で、Proxmox VE 向けの provider と NetBox 向けの provider を使います。

## モジュールがまとめる作業

モジュールが内部で作成するリソースは次のとおりです。

- NetBox の仮想マシンと仮想マシンインターフェースを作成する
- NetBox のプレフィックスから空き IP アドレスを 1 つ払い出す
- cloud-init の user-data をスニペットとして配置する
- Proxmox VE の VM を作成する
- VM を Proxmox VE の HA リソースとして登録する
- VM のファイアウォールオプションとファイアウォールルールを作成する

出力は 2 つだけです。

- `ip_addr` は、VM に割り当てられた IPv4 アドレスをプレフィックス長なしで返す
- `name` は、VM の FQDN を返す

呼び出し側は、この出力を使って、DNS レコードなど、VM の作成後に必要なものを登録します。

## NetBox からの IP 払い出し

IP アドレスは、呼び出し側がアドレスを直接指定する方式ではありません。

呼び出し側は、NetBox のサイト ID とプレフィックス ID を渡します。

モジュールは、そのプレフィックスから空きアドレスを 1 つ取得し、VM のプライマリ IP として登録します。

取得したアドレスは、VM のインターフェースにも紐付けます。

この方式では、アドレスの重複を NetBox 側の払い出しで防ぎます。

アドレスを Terraform のコードに直接書かないため、コードを読むだけでは使用中のアドレスは分かりません。

使用状況の確認先は NetBox に一本化されます。

ネットワークの選択は呼び出し側の責務です。

内部サービス、外部公開サービス、管理用途でプレフィックスとブリッジを使い分けます。

モジュールは、渡されたプレフィックスとブリッジをそのまま使います。

## cloud-init の user-data 生成

user-data は、モジュールが文字列として生成し、スニペットとしてデータストアに配置します。

スニペットを使う理由は、Proxmox VE の API だけではスニペットを配置できないためです。

provider は、スニペットを配置するためにノードへ SSH で接続します。

user-data に含める内容は次のとおりです。

- ホスト名と FQDN を設定する
- 管理ユーザーの名前、パスワード、SSH 公開鍵を設定する
- `qemu-guest-agent` と `zsh` のパッケージをインストールする
- `qemu-guest-agent` のサービスを有効化して起動する

ホスト名は、FQDN の最初のラベルを短い名前として使います。

設定で重要なのは、`ssh_deletekeys` を `false` にしている点です。

既定の `true` では、cloud-init の instance-id が変わるたびにホスト鍵が作り直されます。

Proxmox VE では instance-id は cloud-init の設定から計算されるため、設定の変更だけでホスト鍵が変わります。

ホスト鍵が変わると、認証基盤に登録した鍵と一致しなくなるため、このモジュールでは作り直しを止めます。

スニペットを使わない選択肢も、変数 `use_snippet` で用意しています。

`use_snippet` を `false` にすると、スニペットは作成しません。

その場合は Proxmox VE が生成する user-data に、ユーザーと鍵だけを設定します。

代わりに、パッケージのインストールは行われず、`qemu-guest-agent` も有効にしません。

エージェントが入っていない状態で有効にすると、provider が応答を待ち続けるためです。

この選択肢は、SSH でのスニペット配置を避けたい検証用 VM などで使います。

## 配置ノードの決め方

配置ノードは、変数 `node_name` と変数 `candidate_nodes` で決めます。

- `node_name` を指定した場合は、そのノードだけを候補にする
- `node_name` を指定しない場合は、`candidate_nodes` の一覧を候補にする

候補からは `random_shuffle` リソースで 1 つを選びます。

候補が空の場合は、VM リソースの precondition でエラーを出します。

ランダムに選ぶ方式は、特定のノードへの偏りを避けるためのものです。

配置先を固定したい VM は、`node_name` で明示します。

## HA への登録と node_name の差分対策

VM は `proxmox_haresource` リソースで HA リソースとして登録し、状態は `started` とします。

HA が有効な VM は、障害時だけでなく運用操作でも別のノードへ移動する場合があります。

ここで問題になるのが、Terraform が管理する `node_name` です。

VM が別ノードへ移動すると、実機の `node_name` と Terraform の状態が一致しなくなります。

そのままでは、次の plan で元のノードへ戻す差分が出ます。

このモジュールでは、VM リソースの lifecycle で次を指定します。

```hcl
lifecycle {
  ignore_changes = [node_name, initialization[0].user_data_file_id]
}
```

`node_name` を `ignore_changes` の対象にすることで、HA による移動は差分になりません。

作成時の配置は候補からの選択で決まり、その後の移動は Proxmox VE 側に任せるという分担です。

`user_data_file_id` も同じ理由で対象にしています。

スニペットの配置先ノードが変わっても、既存 VM の初期化設定を書き換えないためです。

## ファイアウォールの設定

ファイアウォールは、変数 `firewall` が `true` の場合だけ有効にします。

有効にした場合は、オプションとルールを別のリソースで設定します。

オプションの既定値は次のとおりです。

- 入力ポリシーは `DROP` である
- 出力ポリシーは `ACCEPT` である
- MAC フィルタと NDP は有効である
- DHCP は有効である

ルールは、変数 `firewall_rules` で呼び出し側が一覧として渡します。

型はオブジェクトのリストで、各ルールが方向、アクション、宛先ポート、プロトコル、送信元などを持ちます。

追加の仕組みとして、メンバー向けのルーティング経路からの SSH を許可するルールを自動で末尾に足します。

この許可は変数 `allow_member_ssh` で切り替え、送信元はクラスタの IP セット名で指定します。

ファイアウォールで接続を許可しても、ログインできるかどうかは認証基盤側の制御で決まります。

## VM 作成後の初期設定

モジュールは VM の作成だけで終わりません。

VM リソースには `local-exec` の provisioner を付けています。

処理は、SSH のポートへ接続できるまで待機し、その後に Ansible の初期設定用 playbook を対象 VM に対して実行するものです。

これにより、Terraform の適用が完了した時点で、VM の初期設定までが終わります。

呼び出し側は、Ansible のリポジトリのルートパスを変数で渡します。

## 呼び出し側の書き方

呼び出し側が書くのは、モジュールの呼び出しと、必要最小限の引数だけです。

引数の中心は次のとおりです。

- `name` に VM の FQDN を指定する
- `candidate_nodes` に配置候補のノード一覧を指定する
- `netbox_prefix_id` と `bridge` と `gateway` でネットワークを指定する
- `cpu_cores` と `memory_dedicated` と `disk_size` でリソース量を指定する
- `cloud_image_id` にインポート元のクラウドイメージを指定する
- `firewall_rules` にその VM に必要なルールを指定する

VM の定義ファイルはフェーズごとに分かれたディレクトリに置きます。

他の VM から参照される VM は若いフェーズに置き、依存関係の解決をしやすくします。

## まとめ

このモジュールの設計は次の 3 点に集約されます。

- IP の払い出し先を NetBox に一本化し、アドレスをコードに直接書かない
- cloud-init、HA、ファイアウォールを VM 定義と同時に作成し、後からの手作業を残さない
- HA によるノード移動を `ignore_changes` で差分から外し、移動は Proxmox VE 側に任せる

VM を増やす作業は、モジュールの呼び出しを追加する作業になります。
