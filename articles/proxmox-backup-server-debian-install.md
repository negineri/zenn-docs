## はじめに

本記事は、Proxmox Backup Server（以下、PBS）を Debian 13 の cloud image にパッケージで入れる構成を説明します。
専用の ISO から入れる方法は使いません。
cloud image を使うと、他の仮想マシンと同じ方法で仮想マシンを作り、同じ仕組みで設定を配ることができます。

PBS は、バックアップのデータを塊に分けて保存するサーバーです。
同じ塊は 1 回だけ保存されます。
2 回目以降は、変わった塊だけを送ります。
そのため、短い間隔でバックアップを取っても、送る量と置く量は小さく抑えられます。

本記事で扱うのは次の 3 点です。

- Debian 13 への PBS のインストール方法である
- データストアに使う 2 枚目のディスクの扱いである
- 利用者ごとの名前空間と権限の分け方である

## 構成の概要

構成は次のとおりです。

- 仮想マシンは 4 コア、メモリ 4 GB で作る
- OS 用のディスクとは別に、データストア用のディスクを 1 枚足す
- データストア用のディスクは 128 GB とし、データストア名は `local` とする
- 管理画面と API のポートは 8007 で、接続できるネットワークはサーバーの範囲に限る
- SSH で入れるのは管理用の利用者だけに限る

設定の適用には Ansible のロールを使います。
ロールの処理は、パッケージのインストール、ディスクの準備、PBS の設定の 3 つに分かれます。
PBS の設定は、ロールが渡す JSON に合わせてそろえる補助スクリプトが行います。
対象が無ければ作り、値が違えば直します。
JSON に無い対象は消しません。

## Debian 13 へのインストール

PBS は、Debian へのパッケージでの導入が公式に用意されています。
手順は PBS の公式ドキュメントの Debian への導入の記載に従います。

大まかな流れは次のとおりです。

- Proxmox のリポジトリの鍵を取得し、チェックサムで正しい鍵であることを確かめる
- サブスクリプション無しのリポジトリ `pbs-no-subscription` を追加する
- パッケージ `proxmox-backup-server` だけをインストールする
- パッケージが追加するサブスクリプション用のリポジトリを無効にする

最後の 1 件には理由があります。
サブスクリプションが無い状態でサブスクリプション用のリポジトリが有効だと、`apt update` が認証エラーで失敗します。
そのため、インストールの直後に無効にしておきます。

入れるパッケージを `proxmox-backup-server` だけに限る点も重要です。
Proxmox のカーネルは入れません。
OS は Debian 13 のまま使い、カーネルまで Proxmox のものに置き換えることはしません。

インストールの後は、PBS のプロキシのサービスを開始します。
メール通知は使わないため、依存で入る postfix は止めておきます。
タスクの失敗の通知は、監視の仕組みで別に受け取る構成です。

## データストアのディスク

データストアには、2 枚目のディスクを ext4 でフォーマットして使います。
マウント先は `/mnt/datastore/local` です。

ディスクの指定には、デバイスの名前ではなく by-id のパスを使います。
`/dev/sda` などの名前は起動ごとに変わることがあるためです。
by-id のパスは、Proxmox 側の差し込み口で決まるため、起動のたびに変わりません。

フォーマットは、ディスクにファイルシステムもパーティションも無い場合だけ行います。
中身があるディスクは作り直しません。
この条件により、ロールを再実行しても既存のデータストアは壊れません。

データストアには次の定期処理を設定します。

- 不要になった塊を消すガベージコレクションは毎日実行する
- バックアップを読み直して壊れていないかを見る verify は毎週実行する
- 一度見たものは 30 日間は verify の対象から外す

ディスクが足りなくなった場合は、仮想マシンのディスクを増やしてからファイルシステムを広げます。
データストアの作り直しは必要ありません。

## 利用者と名前空間の分け方

管理画面に入る利用者には、管理者（Admin）の権限を付けます。
対象は仮想マシンの管理者 1 件だけです。

バックアップを送る側は、利用者を分けます。
分け方は次のとおりです。

- バックアップ元のホストごとに、PBS の利用者を 1 件作る
- バックアップ元のホストごとに、データストアの中に名前空間を 1 件作る
- その利用者には、自分の名前空間だけに権限を付ける
- 付ける権限は `DatastoreBackup` とする

`DatastoreBackup` でできることは、バックアップを取ることと、自分のバックアップを読むことだけです。
バックアップを消すことはできません。
バックアップ元が乗っ取られても、その利用者の権限では保存済みのバックアップを消せません。
これが、この分け方の一番の目的です。

管理用の仕組みには、このサーバーを参加させない点も同じ考え方です。
対象の管理基盤では、参加した全ホストに管理者全員が入れる設定になっていました。
バックアップの置き場にその設定が効くと、管理者のアカウントが乗っ取られたときにバックアップも消せる状態になります。
PBS の管理とクライアントの接続にその管理基盤の利用者は必要ないため、参加させず、SSH も管理用の利用者だけに限ります。

## 世代管理は PBS 側だけが行う

残す世代は、名前空間ごとの prune job で決めます。
既定の設定は次のとおりです。

- prune job は毎時実行する
- 最新の 24 件を残す
- 毎日の分を 7 件残す
- 毎週の分を 4 件残す

世代を消す処理を行うのは PBS 側だけです。
クライアント側の利用者には削除の権限が無いため、クライアントから世代を消すことはできません。
取ることと消すことを分けることで、誤操作と乗っ取りのどちらの場合でも、残る世代は prune job の設定どおりになります。

## クライアントを足す手順

バックアップ元を足す作業は、バックアップ元の側だけで行います。
PBS 側の変数や仮想マシンの定義は触りません。

バックアップ元のロールから、クライアント登録用のロールを呼びます。
そのロールは次の処理を行います。

- バックアップ元に `proxmox-backup-client` をインストールする
- PBS 側に処理を移して、そのホストの利用者と名前空間と権限を作る
- 同じ名前の prune job を作る
- 暗号化の鍵をバックアップ元に置く
- PBS の証明書の fingerprint を読み、接続の設定をバックアップ元に書く

接続の設定には、接続先、名前空間、fingerprint、パスワードのファイル、鍵のファイルが入ります。
バックアップのスクリプトはこの設定を読み、環境変数と引数にして `proxmox-backup-client` を実行します。

バックアップ元を減らすときは、そのロールからクライアント登録用の呼び出しを外すだけで済みます。
PBS 側の利用者、名前空間、prune job、スナップショットは残ります。
戻すときにそのまま使えるためです。
不要になったものは、管理画面で名前空間ごと消します。

PBS を作り直すと証明書の fingerprint が変わります。
その場合は、クライアントにロールを当て直す必要があります。
fingerprint が一致しないバックアップは失敗するためです。

## クライアント側の暗号化

クライアントは、既定でクライアント側で暗号化してから送ります。
方式は AES-256-GCM です。
PBS には暗号化した塊だけが置かれるため、PBS の管理者からも中身は読めません。

鍵はクライアントごとに用意します。
鍵のファイルは、root だけが読める場所に置きます。
ホストを作り直しても同じ鍵が配られるため、前のスナップショットを戻すことができます。

注意点は次のとおりです。

- 暗号化したスナップショットは、鍵が無いと戻すことができない
- 管理画面では、暗号化したスナップショットの中のファイルを見ることはできない
- 戻す処理は、鍵を持つクライアントから行う
- verify は、暗号化した塊では CRC-32 だけを確かめる

鍵の元になる値を変えると鍵も変わります。
その場合は、変える前のスナップショットを戻すための鍵を別に残しておく必要があります。

## ISO から入れる方法を選ばなかった理由

以前は専用の ISO から PBS を入れていました。
その方法では、導入と設定に手作業が残り、作り直しが重くなります。

パッケージで入れる方法では、cloud image を使う他の仮想マシンと同じ土台に乗ります。
仮想マシンの作成、設定の配布、監視の組み込みを、既存の仕組みのまま使えます。
作り直しの手順も、他の仮想マシンと同じ流れで済みます。

## まとめ

要点は次の 3 点です。

- PBS は専用 ISO ではなく、Debian 13 の cloud image にパッケージで入れる
- クライアントごとの利用者と名前空間に `DatastoreBackup` を付け、取ることと読むことだけを許可する
- 世代を消す処理は、名前空間ごとの prune job で PBS 側だけが行う

取る権限と消す権限を分けることが、バックアップを残すための中心の設計です。
